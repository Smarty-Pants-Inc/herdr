Herdr が `config.toml` から読み取る正規キーを、フラットに一覧して絞り込めます。
ガイド付きの設定手順や各オプションの背景は[設定](/ja/docs/configuration/)を参照してください。

コメント付きのデフォルト設定全体はいつでも出力できます:

```bash
herdr --default-config
```

カスタムコマンドバインディング（`[[keys.command]]`）はユーザー定義のテーブルのため、
ここではキーごとに掲載していません。
[カスタムコマンドキーバインド](/ja/docs/configuration/#カスタムコマンドキーバインド)を参照してください。

## グループ化サイドバー

デフォルトのサイドバーは Machines 表示です。接続済みエンドポイントのワークスペースを
組織 → プロジェクト → レーンでまとめるには、**クライアントのローカル** `config.toml` に追加します:

```toml
[ui.sidebar.grouping]
enabled = true
```

UI の `reload config` で反映します。すぐに Machines 表示へ戻すには、同じテーブルで
`enabled = false` にして再度設定を読み込んでください。保存済みマシンのプロファイルと
カスタム行レイアウトは変更されません。

以下のトークン名設定はすべて省略可能な文字列です。汎用のグループ化項目を、既存の
**ワークスペースのメタデータトークンキー**に対応付けます。`$` プレフィックスは付けません。
デフォルトはランチャーの契約に一致します。別のランチャーは別のキーを報告し、対応付けを
変更できます。Herdr は組織ファイルを読み取らず、パス、マシンラベル、ワークスペース名から
プロジェクトの識別情報を推測しません。

| `ui.sidebar.grouping` 内の設定 | デフォルト | ワークスペーストークンの意味 |
| --- | --- | --- |
| `enabled` | `false` | クライアントのグループ表示を有効化（真偽値）。 |
| `org_id` | `"smarty_org_id"` | 安定した組織 ID。 |
| `org_label` | `"smarty_org_label"` | 読みやすい組織ラベル。 |
| `project_id` | `"smarty_project_id"` | 組織内の安定したプロジェクト ID。 |
| `project_label` | `"smarty_project_label"` | 読みやすいプロジェクトラベル。 |
| `lane_id` | `"smarty_lane_id"` | 安定したレーンまたは割り当て ID。 |
| `lane_purpose` | `"smarty_lane_purpose"` | 短い作業目的。 |
| `issue` | `"smarty_issue"` | 追跡用 Issue の表示ヒント。 |
| `host` | `"smarty_host"` | 実行ホストの表示ヒント。操作の接続先ではありません。 |
| `role` | `"smarty_role"` | ワークスペースの表示上の役割。 |
| `lead` | `"smarty_lead"` | 担当リードの表示ヒント。 |

対応付けできないワークスペースは **Ungrouped** に残ります。通常の Local の作業や、
`workspace.report_metadata` に未対応の互換サーバーのワークスペースも含まれます。
識別情報が欠けている、不完全、または矛盾していても、ワークスペースを隠したりサーバー更新を
要求したりしません。サーバー復元後はランチャーがメタデータを再報告する必要があり、
それまではメタデータのないワークスペースを Ungrouped に表示します。

グループ化はクライアントの表示だけを変更します。ワークスペースやペインの操作は、元の
エンドポイントとそのローカル ID に基づいて送信します。グループ ID、Issue、ホスト、リード名は
操作先を決める権限を持ちません。既存のトークンと接続を使い、**サーバーやエンドポイントの
コーデックは変更しません**。切り替えと CLI の操作先については
[マシンへの接続](/ja/docs/connecting-machines/#グループ表示)を参照してください。
